# Prepared dynamics and body-rebound decisions

Original read-only design audit, 2026-10-08; the implementation evidence below is dated 2026-10-09. The original audit narrows Family5 from `native_source_fighter_hook_remaining_audit.md` to the two hooks required by Peach.

## Immutable prepared contracts

Append `NativeScriptFighter_DynamicsInteractionStart` and `NativeScriptFighter_BodyRebound` before HookCount in `native_script_fighter.h`, with table rows in `native_script_fighter_hooks.c`:

| Source event | Result | Arguments | Missing hook |
| --- | --- | --- | --- |
| `dynamics_interaction_start` | I32 | I32 set, I32 set_count | I32 zero |
| `body_rebound` | Bool | none | false |

The existing event descriptors already specify these exact signatures/defaults (`native_script_events.c:585,603`). Dynamics payload names are `event.set`/`event.set_count`; no additional payload schema is needed. The I32 result is a threshold used by `lb_8001044C`, not a bone index: `lb/lb_00F9.c:561` compares `first_active <= loop_index`. Preserve negative and large I32 values; do not clamp them to the bone count.

`nativeScriptFighter_PrepareProgram` already resolves root-owned callbacks by event name, verifies result and formal types, rejects duplicate slots, and stores function IDs (`native_script_fighter_program.c:79–138`). Adding the rows makes these existing event contracts preparable; Article/Effect callbacks still follow their own owner validation. Hook IDs reside in immutable `NativeScriptFighterProgram.hooks[]`, not mutable instance callback slots. The generic Run entry checks exact arguments, dispatches via prepared function ID and preserves output on Error/SourceRetired (`native_script_fighter_actor.c:151`). Missing slots produce typed zero/false in `runFunction`. No actor state field, tick allocation, callback-pointer shim or snapshot-record expansion is needed. Program identity already covers code/layout/parameters; snapshots pin that program identity and restored authored state.

## Dynamics continuation

Actual call chain: `Fighter_8006D9AC` checks the native suppression flags and calls `ftCo_8009E0A8`; E0A8 calls `ftCo_8009DD94(gobj,x2228_b1)` once. DD94 is not a second call made by the Fighter caller. There is no continuation in that outer caller after E0A8. Inside DD94 the order is:

1. Cache `dynamics_num` and native `dynamic_bone_sets`; temporarily adjust the root X scale on Flatzone.
2. Compute ground-collision policy; currently optionally call Definition's `on_dynamics_ground_collision`.
3. Call `ftColl_8007AF60`, then `ftCo_8009E614` (which contains another Definition wind decision and possible dynamics reset).
4. For each set, obtain first-active interaction threshold, then call actual `lb_8001044C`.
5. Restore temporary Flatzone root scale and update native dynamics joint matrices.

Proposed source branch directly calls Run(DynamicsInteractionStart, `{I32 i,I32 cached_count}`, 2, &result) before each existing `lb_8001044C`. Recheck the captured `NativeFighterLifetime` **after every decision, even if its value is zero**, before reading cached `fp`/`dyn` or invoking the next native stage. A source actor must never take Definition/Peach/Mewtwo fallback; an absent source hook returns zero for every set. A selected source package with a missing/unusable actor must stop, not be mistaken for an ordinary native actor merely because IsAttached is false. Preserve the existing native branches for genuinely non-source actors.

Capture the actual selected root and dynamics set count/descriptor-data identities at entry. The native fixed array has `Ft_Dynamics_NumMax=10`; native initialization requires count below ten (`ftdynamics.c:92`), so source admission is `0 <= count < 10`. A hook can call engine operations which reset/unload dynamics or change actor generation; lifetime validity alone does not prove cached descriptor chains remain current. After authored decisions verify count and relevant captured descriptor identity before dereference, rather than reacquiring a replacement set and continuing under an old threshold. Do not mutate or constrain legitimate threshold results.

Flatzone needs explicit exit handling: restore the borrowed root scale on a script fault while the same physical source/root is still valid; do not access a retired/replaced root. Avoid calling the normal matrix-update tail after a failed decision. Capture root/class identity before its temporary mutation. This is necessary because an unconditional early return would leave a live faulted actor's root scale changed.

The wind/ground-collision Definition calls are separate policies, not newly supported by these two rows. On a source actor skip their legacy callback branches entirely, leaving their existing generic baseline until their own source contracts migrate. Their native reset operations are also continuation boundaries, so guard them before resuming DD94. A full dynamics-policy migration must later cover both wind sites (`ftdynamics.c:596,665`); do not mark them accepted merely because the interaction hook now prepares.

## Recipient body rebound

`nativeFighterContact_ReboundAllowed` (`native_fighter_contact.c:7`) asks the **recipient** stored in the caller's `unk_gobj`. No-contact or null relation returns true; an invalid referenced recipient returns failure. Its current decision uses recipient Definition, then exact stock Mars/Emblem/Peach motion predicates. The native Peach special-S `doAirEnd0` (`ftPeach/ftpeachspecials.c:78`) duplicates this decision with fewer guards. `native_fighter_module.c:1084` exposes the shared query to the reference exporter; no direct binding currently exists.

Capture physical pool references/generations, user-data identity, kind/owned program/storage for both source and recipient using the existing `NativeFighterLifetime` contract. Read/cache `unk_gobj` only after source capture; validate recipient classification/pool membership before dereference. If the recipient is interpreted, call Run(recipient, BodyRebound, NULL, 0, &result) directly. An absent prepared hook is false. After **either true or false**, validate both captures plus the unchanged contact relation before any publication/native continuation. A reflected or reselected contact must not cause a second lookup or decision on another recipient. A source recipient never falls through to Definition or kind predicates. A physical ordinary recipient retains the actual ordinary native policy, including exact stock motion IDs.

The smallest native-only safe change can retain the Bool query and return false on any invalid continuation. However, that ABI cannot distinguish an authored false from a fault/retirement in the recipient. The future direct `collision.contact_rebound_allowed()` binding should not silently publish false for a framework failure. Recommended coherent API change is one substantive status-bearing query, e.g. `NativeScriptVMStatus nativeFighterContact_ReboundAllowed(Fighter_GObj*, bool* allowed)`, leaving `allowed` unchanged except on Ok. Both the native Peach caller and typed binding then call this directly; they stop on non-Ok, and only interpret `allowed` after a successful query. Do not add a Bool wrapper around it. The test-only reference Host field/emission and its fixtures must be adjusted together if this API is selected. If the old reference ABI is intentionally retained, keep it isolated from the direct production route rather than using it as the source binding's status contract.

The source caller and recipient may be the same actor. Existing synchronous Run can reenter the shared VM; use its bounded frames/status semantics and retain both captures without a special native function pointer. Test recursion exhaustion as an Error, not a false decision, and leave payload/VM/receiver scopes balanced.

## Changed units and focused proof

* Core: `native_script_fighter.h`, `native_script_fighter_hooks.c`; generic preparation/Run should require no new specialized dispatch code. Extend existing prepared-hook ABI/default/duplicate/owner and snapshot identity tests.
* Dynamics: `ftdynamics.c` DD94 plus the guard boundaries surrounding its existing wind/reset calls. A focused real-body fixture should compile root callbacks through actual frontend/Prepare/actor/VM; compare ordered `{set,count,threshold,bone,ground policy}` delivery against the stock/reference loop. Cover zero sets, multiple sets and signed thresholds; one callback per set; no native loop continuation after fault/retirement; descriptor reset/replacement; Flatzone live-fault scale restoration.
* Contact: `native_fighter_contact.c/.h`, the duplicated native `ftpeachspecials.c` consumer, then the genuine query binding/catalog when authorized. Run actual source actors and native contact logic: ordinary exact predicates, source recipient true/false/default, foreign program, caller/recipient retirement, relation changes, same actor, nested decision and recursion exhaustion. Both result directions must receive identical postguards.
* Existing reference boundaries: `tests/native/aerial_policy_test.c` covers legacy Bool contact and native callback hazards; `peach_fighter_composition` compares original dynamics calls; `fighter_common_policy_test.c` tests generated event contracts. These are useful oracles but do not prove interpreted hook dispatch. Update only affected API consumers if the status ABI changes.
* Controlled test leaves may isolate bone integration math/render/collision and lifecycle mutation. Actual GObj pools, registration, source actor storage, prepared hook IDs, VM and shared lifetime checks must run. A loop trace comparison does not claim dynamics solver numerical parity or asset-import admission; retain those limits explicitly.

`body_rebound` now prepares as a root Bool0 hook. The direct `collision.contact_rebound_allowed()` backend calls the shared status-bearing contact kernel, with result publication only on Ok. Both retained actors must remain physically and logically current after either gameplay result. Source admission also verifies the actual selected data/table/layout through `nativeScriptBindings_SourceFighterLayout`. The native Peach continuation and test-only Host/exporter use that same status-bearing signature directly. The changed Host field moved to the structure tail so the existing offset fingerprint rejects the former Bool-only binary ABI.

## Implemented dynamics-interaction slice, 2026-10-09

`dynamics_interaction_start` now prepares as I32(I32 set, I32 set_count). The actual DD94 loop calls the prepared code ID once per set, uses an absent hook's typed zero, preserves the signed I32 threshold without clamping, and validates the retained actor and graph schema before each solver continuation. Source admission verifies the selected owned data/layout. Its stack capture records the root/class/object kind, set count/head/count/bone IDs, collider count, attachment mask and every linked dynamics node's next/joint/class identity. The bounds come from the actual native limits: fewer than ten sets and 320 nodes in the fixed dynamics allocator. Native simulation values within those descriptors remain mutable.

Source scheduling uses the generic ground/scale baseline and bypasses the Definition, Peach/Mewtwo/Koopa and native wind decisions. Both E614 and E7B4 retain genuine common animation/reset behavior. `dynamics_wind` and `dynamics_ground_collision` are still unsupported authored contracts; their baselines are not acceptance of those hooks. Ordinary native/reference policies retain their existing decisions.

After a failed decision or invalidated descriptor, DD94 skips the remaining solver/matrix tail. A borrowed Flatzone root scale is restored only if its original physical actor/root remains current; logical VM fault alone does not leave that live root scaled. Physical replacement or logical retirement cannot authorize touching an old root. Native JObj/dynamics allocations have no per-address generation API: the pointer/class/link checks do not detect arbitrary free-and-recreate at identical native addresses with identical metadata, and no actor-only rollback or graph resurrection guarantee is made.

`tests/native/script_fighter_dynamics` passed 2,495 checks across 223 cases, with 96 source scheduler entries and 120 ordinary native trace pairs. Its immutable receipt is `A:/FreakMelee-test-archives/script-fighter-dynamics-final/receipt.json`. Actual frontend/preparation, actors, storage, event payloads, VM, GObj pool, class predicate, descriptor free-list/unload, collider preparation and joint-flag bodies execute. The numerical solver, coordinate transform, HSD matrix construction and unrelated animation leaves are controlled. The pre-batch reference is pinned to `45ac45dce93fd6a8540f1686fcd14e445341787b`; its existing E7B4 `var_r3` warning is independently reproduced and is the sole changed-body warning exception. No DAT import, numerical dynamics solver or gameplay acceptance is claimed.
