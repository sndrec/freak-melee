# Source-owned indexed resources

> Dated evidence, not the current backlog. Results and limitations below apply
> to the recorded build. See the [current plan](../../PROJECT_PLAN.md) and
> [evidence index](checkpoint_index.md) before treating an old pending item as new work.

The interpreter now resolves and executes bounded Item/Article resource
collections. Exact immutable recipes belong to the published Item program.
Capacity is 2–90; the optional borrowed fighter part must lie beyond the final
native rig table and below 140. Final part count includes inserted omissions:
Link's 75 joints and one omission produce 76 parts. Metadata and scene admission
reject a reservation that overlaps those parts.

The runtime no longer looks up a generated-code Definition/ArticleLogic to own
these collections. Fixed scene backing supplies actual ItemLink payloads and
model graphs. The limits are sixteen collections of ninety nodes; graph
replacement reserves a spare graph. No node operation expands an arena on a
tick. Pinned source packages retain descriptors until their scene drains.

Selectors retain a dynamic index once, and joint paths are decoded during
preparation. Model names resolve to owner-scoped ordinals. Matrix methods use
an exact owned Float[12] declaration lowered to a prepared integral argument;
no raw script pointer or ordinary-array scalar reinterpretation is involved.
Healthy false vector/matrix queries retain native zero defaults. Retirement or
substitution prevents publishing outputs.

Cleanup retains the physical borrowing fighter separately from its revocable
attachment. It removes matching part, capture and hitbox references before
graph destruction. Endpoint and graph generations are checked independently,
including orphaned endpoints. Sweeps and effects defer payload destruction
until active resource operations return.

Collection/allocator metadata and real main-heap backing are covered by the
current Regions/Pages owner. This does not replace page tracking with compact
whole-match snapshots. The old Definition-backed runtime test registrations
were replaced by source-owned frontend, kernel and history cohorts; historical
fixtures remain available as stock comparison inputs.

## Animation boundary

The native resource animation core uses explicit prepared
graph/subtree/bundle applications and an exact controller-origin ledger. It
retains the canonical published program after comparing its owned package row.
Scene preparation without application tuples admits static graph controls,
but rejects Add. The public interpreter still rejects resource animation
methods until source-owned application preparation is connected. There is no
hash fallback, invented Item context or controller-provenance bypass.
