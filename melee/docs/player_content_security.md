# Player content and network security

Validate downloaded data before a parser, renderer, script runtime or match uses it. Keep the resulting objects for the lifetime of the scene. Check each incoming packet against the transport peer and the local session before using its contents.

## Scripted effect construction

When a fighter package loads, the importer counts the joints, meshes, materials, textures, polygon batches, skin influences, constraints, particle entries and animation records in each effect model. Creating a model costs at least 64 units. A match can spend 4,096 units per simulation tick and keep 8,192 units in live models. Fighter moves and fighter-created items share those limits. Removing a model returns its live units. The next simulation tick replenishes the construction budget.

The deferred effect queue holds up to 256 requests. A simulation tick can allocate up to 256 requests, even if they are flushed immediately. The separate stock animation queue holds 32 roots. Removing an effect before its first animation update also removes its root from that queue. Rollback restores the counters with the rest of the effect state.

## Joint constraints and model particles

When the game imports a model, it checks that each bone constraint can find its target inside that model. A cached costume attachment gets the same check when it is opened as a separate model. If a prop needs a bone that belongs to the rest of the costume, the attachment load fails and the full costume stays usable. The importer also checks that the renderer supports the model's billboard mode.

An animation can disable an inverse-kinematics hint or move its target onto the joint. In those frames the joint keeps its animated transform. The solver can aim the bone again as soon as it has an enabled hint and a direction. A survey of 161 named player-model roots from the US 1.02 disc and Goomba found no constraints in those roots. Two purpose-built rigs exercise the one- and two-segment solvers. World objects used for camera position, camera interest and lights come from menu and stage scene descriptors. Fighter, costume, article and scripted effect models do not import those scene descriptors.

## Stock effects and particles

Stock effect models now use the same construction budget as packaged models. Each stock model costs 64 units. All fighters and items together can create at most 64 stock models in a tick and keep 128 alive. Retiring a model returns its live units immediately.

A tick can start 256 particle generators, run 1,024 emission iterations and create 1,024 particles, including child particles. At most 512 generators and 4,096 particles can stay alive. When the tick budget runs out, an emitter drops excess whole emissions and carries its normal fractional rate into the next tick. Removing a generator before its first draw also removes its pending joint update before the slot can be reused. Rollback restores the counters along with the particle state.

The native importer checks each command’s texture slot and numeric parameters before installing the particle bank. A survey of 1,037 commands across 27 effect and 23 stage archives from the retail disc found that all met those checks. ## Chat and lobby connections

Global chat keeps a seat for every open connection, including players waiting for a heartbeat. A player can reconnect to their own seat in a full chatroom. The service accepts the replacement before closing the previous socket. An unsuccessful join leaves the existing connections usable.

Each chat socket can send a burst of 32 messages and regains one message every 125 ms. The service checks packet size and available capacity before querying an account or queuing work. A signed-in socket can have up to 32 commands waiting for authentication. Its rate limit survives hibernation.

Global chat retains a peer’s account binding while the socket is open or the chat history still refers to the peer. A lobby keeps the binding for an active player, a pending join, a reconnecting player, a retained chat message, stage selection history or a Quick Play assignment. On membership changes it removes bindings that have outlived those uses, even while other players stay in the lobby. The friend list and offline gifts belong to accounts and survive a lobby closing.

All 121 signaling tests passed. They include a full chatroom with players in heartbeat recovery, a returning account, and a chat sender whose last stored message ages out after they leave. On the local service, two native clients transferred Goomba and compared 800 and 796 confirmed frames with zero mismatches. The receiving client replayed 3,991 ticks.

Each pair of active players negotiates its own gameplay connection. When ICE reports a failure, the pair can reconnect through lobby signaling. Both ends identify the current attempt in their connection descriptions so a delayed description from an earlier attempt can be discarded. Peers can create three connections immediately. Further attempts share one new connection per 250 ms, and repeated failures on one route back off to 16 seconds. During a match the existing five-second input timeout still applies.

Chat, lobby browsing and room joins share a limit of 120 WebSocket connection attempts per minute per network at a Cloudflare location. The check happens before account lookup or room access. A room allows 32 membership changes awaiting an account or session check. A guest returning to an assigned Quick Play party proves ownership with their installation identity or the private connection ID issued to their seat. The source party keeps the installation identity locally. A signed-in player can also return using the account already bound to that seat.

The lobby browser reads up to eight summaries from the directory per page. It can list up to 512 lobbies for the player's build. Each room publishes its own title, host, seat counts and match status. A listing expires 45 seconds after its last reachable participant stops sending input or heartbeats. Reconnecting during the room's recovery period restores the listing. ## Fighter bones and animation tracks

The importer distinguishes permanent costume bones from slots reserved for attachments. Camera, collision, hurtbox, dynamics, part-animation and effect references that rely on a bone being present must point to a permanent bone. A hitbox can use a temporary bone while its attachment is present. When an animation contains a track for an absent attachment, the animation player consumes that track and applies the following track to its intended bone. Both full-body and partial animations use this rule. The Workshop also refreshes a cached demo pose when the underlying animation changes.
