# Peach versus activation proposal

This is a read-only activation audit, not an activated port or API commitment.
The live checkout was inspected after the accepted Parasol producer checkpoint,
at HEAD `5c504205f265eb53da0fa2969765c0a4717e64a3`. No game or build was run.
Only this document was added. Kirby copy behavior and video-only demo scenes
remain outside the agreed versus scope.

**Peach is not ready to declare independent behavior.** There is still no Peach
clone definition/registered project/default FMS in the live clone set. The
accepted candidates are source-tested components, not a complete fighter or
complete replacement article table. Register an inherited staging definition
first; activate authored phases only as complete coherent batches, then remove
inheritance after the common decision boundaries below are owned and tested.

## Remaining generic core contracts

These are source contracts for root to design, not promised final DSL spellings.
Implement them at actual common boundaries and call sites directly. A late
`on_tick` patch or a stock fighter-specific handler call is not equivalent.

1. **Ordered optional aerial action decisions.** Replace the two raw Float
   tests at `ftCo_Fall.c:136/142`, `ftCo_Jump.c:188/191`, and
   `ftCo_JumpAerial.c:346/356`. Bool return means the script entered an action
   and the caller stops its IASA sequence. Distinguish the first manual-start
   stage from the later descending/held-jump stage. Keep Jump's `mv.co.jump.x4`
   and aerial-jump command0 gates in their original positions, with all earlier
   item/special/Parasol checks and intermediate aerial-jump priority unchanged.
   Snapshot/check source identity after callback. These cannot be owned through
   existing `on_aerial_jump`, which controls jump entry rather than common IASA.

2. **Grounded motion-transition reset.** At `Fighter_ChangeMotionState`,
   `fighter.c:1213`, the original resets Float availability inside grounded
   setup before later setup/callbacks. A generic grounded-transition hook at
   that phase must replace the raw Peach reset. `on_landing` alone misses
   grounded transitions and changes ordering. Own `has_float` as Bool state.

3. **Forward-smash entry ownership before common setup.**
   `ftCo_AttackS4.c:decideFighter` currently calls `doEnter` then
   `on_forward_smash_start`; stock Peach bypasses `doEnter` entirely.
   A complete authored entry must occur once, keeping shared item throw/swing
   handling and facing assignment first. During this audit root implemented
   `on_forward_smash_enter(gobj, float angle)` directly before the existing
   post-entry hook; the final working caller now invokes it and returns without
   `doEnter`. This closes the source ordering contract, pending shared build/
   fixture acceptance and authored Peach implementation. Existing smash charge
   fields are a separate shared charging contract.

4. **Common held-article status/animation dispatch and motion choice.**
   `ftCommon_8007E83C` and `ftGetParasolStatus` hardwire Peach item state/rate
   mapping and `it_802BDA40`/`it_802BDD40`/`it_802BDDB4`. Support declared
   authored article policy at these boundaries while preserving ordinary
   engine Parasol behavior. Status uses real item state; proportional rate is
   fighter animation rate times **15 or16**, divided by supplied divisor (zero
   uses fighter rate directly). Dispatch executes on the actual held article,
   not a possibly different saved creator handle. The selector in
   `ftCommon/inlines.h:ftCo_ItemParasolGetFallMotionId` must let the owned
   package select369/370 without `kind==Peach`/private union access. Preserve
   common open/fall timers/previous motion and landing behavior; merely
   executing common callbacks still invokes these dependent paths.

5. **Parasol cleanup/resume policy at three common boundaries.**
   `ftCo_Landing_Enter` clears aerial Toad use and conditionally cleans Parasol
   after storing `mv.co.landing.allow_interrupt`; expose that Bool or supply
   the original entry argument to an ordered hook. Existing landing_action
   can then perform authored state/cleanup. `ft_8008A348` cleans a held owned
   Parasol after down/hammer/air gates but before Wait; add a generic optional
   neutral-entry policy there. `fn_800D2890` must select the actual special
   fall resume action for saved owned motion370, without raw Peach equality.
   Keep the fighter timer-expiry path (`fighter.c`, x2221_b4/x2104) in this
   audit: it branches on held Peach-Parasol kind before calling special Fall.
   Item-kind identity is valid owned metadata, but its resulting route must
   honor the declared article and owned motion policies above.

6. **Live contact-recipient rebound decision.**
   Side-B's `doAirEnd0` reads x221C_b5, current `unk_gobj` and recipient
   `on_body_rebound`, then stops unless the recipient permits rebound.
   Existing `target.is_fighter` is only a raw classifier read and does not
   expose that flag/policy. Supply a generic generation-validated contact
   query/policy at this real hurtbox callback, with original null/no-contact
   semantics, declared recipient callback and shared stock fallback. No raw
   pointer escape. The authored attacker owns velocity/command2/end transition;
   authored Peach recipient permits only365/367. Hurtbox callback binding and
   facing-change helpers already exist; the reverse-velocity callback can be a
   true authored body writing `-facing*abs(velocity)` on the two components.

7. **Small common aerial-attack/input primitives or exact generic inputs.**
   Float calls `ftCo_800DF478` (current-versus-previous C-stick threshold edge),
   `ftCo_AttackAir_GetMsidFromCStick`, `itGetUseKind`, gun-shoot air entry
   `ftCo_800CDDA0`, and item-throw check `ftCo_80095328(gobj,NULL)`.
   These direct generic helpers are not currently all exposed. Existing
   `controls.aerial_attack_actions()` emits the jump check `ftCo_800CB870`,
   not the needed selector or entry; do not use it as an attack substitute.
   Minimal generic queries/actions can expose those actual common operations,
   or expose their precise previous-stick/use-category inputs for real script
   translation. Shared attack-air entry itself is a short initialization body
   that scripts can author using a chosen motion and KeepFastFall transition.
   Direction thresholds are common engine tuning, not Peach-specific APIs.

8. **Live held article state/frame access for inactive predicate.**
   `notUsingParasol` calls `it_802BDC38(fp->item_gobj)` during common
   LandingFallSpecial: actual held state2 and frame>=16. The article can
   query its current holder through typed exports, but the holder helper
   cannot yet read the arbitrary live held article's phase/frame directly.
   Extend generic live-item query or typed article-recipient return support;
   do not approximate with a cached ticking state field or assume the held
   article equals the recipient's original saved handle. This also supports
   contract4's exact current-item status routing.

9. **Generic collision callback lowering.** Float/FloatFall call the already
   Host-bound `ft_800831CC` with the common ledge predicate and
   `ft_80082B1C` landing callback. Current DSL `collision.air_special_landing`
   synthesizes only special-landing callbacks; let the actual generic Host
   accept an authored landing callback as well. Its body can use existing
   `collision.basic_landing_velocity_threshold`, `state.wait()` and
   `state.basic_landing()` to preserve the strict velocity comparison.
   This is a compiler/lowering gap, not a new collision solver or Peach API.
   FloatAttack's `ft_80082C74(..., ftCo_LandingAir_EnterWithLag)` is reproducible
   with `collision.landed` then basic landing: that actual landing helper
   recognizes only common aerial IDs65..69; Float IDs344..348 take its basic
   landing fallback even when command0 is set. Preserve this real float-cancel
   path; do not add ordinary aerial landing lag by inferred move similarity.

Two Parasol source quirks belong in contract4's comparison. Startup animation
writes `motion_id=FallSpecial` immediately before the common open entry, so its
saved previous motion is FallSpecial; support that explicit previous-motion
fact rather than requiring a script to corrupt engine motion identity. The
called `ftCo_800CEFE0(gobj,int)` currently ignores its Int argument and uses
common x59C for the timer, with blend10; the source's Peach x90 branch does not
actually change that timer. Do not silently make the unused tuning effective.

Cross-fighter issue: stock Bowser down-throw in `ftCo_Throw.c:194` still tests
victim raw Peach/Zelda kind. The already authored Bowser uses generic victim
animation-family metadata and supports a custom Peach. Update the stock common
boundary to the same immutable animation family for stock-versus-clone parity;
do not force Peach behavior inheritance just to preserve the victim pose.

## Suggested bounded implementation and acceptance order

1. Add inherited registered Peach clone/rig/assets and a single unregistered
   integration script assembling accepted constructor, complete Turnip phases,
   typed cleanup and producer. Author reset/presentation/aerial-jump/dynamics/
   CPU/body-rebound. Reimport all parameters through the real project workflow.
2. Complete Toad+Spore and down-B fighter callbacks against current SDK,
   comparing full actual generated source and exact cue/attachment/guard paths.
   Include first/reused aerial boost and landing reset once contract5 exists.
3. Close generic Parasol status/dispatch/live queries/common boundaries, then
   complete up-B plus article and explicit369/370 common policy dependencies.
   Reuse healthy producer/cleanup matrices and add open/close/timer/landing/
   ordinary-Parasol/reused-owned/mushroom-resume cases.
4. Close contact query and translate Side-B+Explode as one batch: no-contact,
   counter recipient allow/deny, walls/ceiling/landing, smash selection,
   creation flags/expiry and facing reversal. Compare actual calls/RNG order.
5. Close pre-smash entry plus Float common boundaries/input operations, then
   author smash and all eight Float/FloatFall/FloatAttack states. Test actual
   common callers, suppressions and priorities as well as generated bodies.
6. Only after every custom phase/global lifecycle/article callback and common
   dependency is owned, declare independent behavior and run root-coordinated
   hidden/muted/fast drawn complete-versus comparisons and deterministic
   authored replay. Source-only acceptance is not drawn gameplay acceptance.

Keep the deliberate removal of the rare/face loops' dead final out-of-bounds
weight read documented. The confirmed collision-mask int-bool lowering and
ordinary saved-scale overlay defects were real native representation repairs;
the accepted Turnip/source baselines already incorporate them. Do not recreate
those bugs, mask digest fields to hide changes, or claim exact RNG/undefined
stock behavior where a deliberate safe behavior difference is accepted. Test
missing/stale/removal cases separately from healthy retail parity, preserving
generic lifetime guards and the producer's explicit invalid-rig discard policy.
