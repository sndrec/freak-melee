# Game & Watch owned load policy — SDK61 source acceptance

Unregistered source fixture. Accepted behavior/renderer namespaces and defaults remain unchanged. No full fighter, constructor, rendered or gameplay acceptance is claimed.

```powershell
python -B tests/native/gamewatch_load_composition/run.py --snapshot .local/baseline61 --output A:/FreakMelee-test-archives/gamewatch-load61-reproduction
```

The runner verifies every frozen input before and after testing and records exact source, generated-input, compiler and command hashes. Final receipt: `A:/FreakMelee-test-archives/gamewatch-load61-final/receipt.json`. The matrix compares 4,608 healthy original/generated pairs: 512 stock palette/graph/initial-state configurations and 4,096 edited channel/width cases. No case filtering is used.

The complete original `ftGw_Init_OnLoad` body executes, including actual `PUSH_ATTRS` copying into allocated fixture backup, native empty Panic charge, width, outline and diffuse writes, visibility pointer install and all ten original article registrations. Registration calls are controlled sinks that assert source order, kind and distinct immutable record pointers. Authored registration belongs to package metadata rather than a scripted stock handler; this fixture does not claim that registration is implemented by the callback.

The actual generated load callback owns secondary-pass material policy, ordinary Panic charge, instance width, packed outline RGBA, costume-selected diffuse RGBA and declared visibility asset10 installation, in defined source order. The actual complete `ftMaterial_800BFB4C` and `HSD_JObjGetDObj` bodies execute over bounded HSD model graphs, including missing MObj/material/root and instance joints. The comparison checks all six material records, palette bytes, width, flags, Panic charge, lookup binding and untouched visibility bookkeeping. Visibility installation itself is a controlled Host publication boundary: real active-package/load-window validation belongs to root’s separate engine fixture.

Raw USA v1.02 `PlGw.dat` bytes supply one Float width and twenty Byte fields (each an owned Int). The fixture’s explicitly controlled parameter-import step reads those actual bytes into typed editable FMP fields and removes the DAT recipes before generating the callback. This is not the normal `import-parameters` tool or a stock clone acceptance. GameWatch has no normal copied base/clone-stock route yet; the generated module uses an inherited fixture base with one inert motion entry solely to satisfy ordinary generated storage requirements. No motion callback runs.

Common initialization already clears x2222_b6, which the fixture preserves as the real load precondition. The source x2223_b1 write has no readers and is deliberately omitted. A custom invalid costume index has an explicit palette0 authored fallback; original indices0..3 are the strict comparison domain, and invalid original array reads are never executed. Positive and negative finite nonzero edited widths are measured. Invalid widths are handled by the generic setter contract, not claimed as original-source pairs.

Color/material writes are CPU-visible source evidence only. HSD allocation, full costume importer, constructor/resource binding, GX, material shader pipeline, pixels and gameplay remain outside this fixture. Historical first-through-third setup failures are retained in their separate A: outputs; the final receipt is the acceptance input.
