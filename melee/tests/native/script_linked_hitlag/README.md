# Linked-hitlag source/actor/native cohort

Run `run.py --compiler <MSVC-target clang.exe> --output <fresh A: directory>`.
The console is hidden; no game, shared build or user project is touched.

The cohort links actual source parsing/indexing/compilation, metadata preparation,
bytecode, Fighter actor, VM, catalog, GObj pool and linked-hitlag backend. It
extracts the exact SourceAlive/SourceFighterLayout guards and Hitlag property
routing case; unrelated properties and native leaves retain the rejecting or
controlled scheduler fixture boundary. Selected source package/data/motions are
controlled inputs, not an imported retail fighter acceptance claim.

Native comparisons use actual `Fighter_UnkSetFlag_8006CFBC`,
`nativeFighterRelations_Link/LinkedId`, and creation-ID lookup bodies. Cases
cover stock and interpreted peers, signed high-bit IDs, one-sided relation
writes, conditional release flags, healthy absence/self, stale creation stamps,
physical retirement/reuse, faulted peer/default reads, source schema/type/width
rejections and unpublished outputs. There is no invented synchronous callback
inside these native setters. Actor snapshot coverage restores native Fighter
fields explicitly alongside packed actor state; it is not Pages history proof.

The receipt fingerprints executed source, generated excerpts, defining headers,
compiler and documentation. This does not prove whole-match hitlag timing,
recursive scheduler callback behavior, asset import, rendering or gameplay.
