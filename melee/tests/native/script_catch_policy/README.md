# Grouped owned catch policy fixture

The runner uses the actual compiler, hook preparation, actor storage, VM, typed
Object import, GObj pool and selected Catch/CatchPull/CatchWait/CaptureWait,
CatchAttack/Throw/Thrown/AirCatch and heavy-pickup kernels. Healthy native ordering is compared
with renamed bodies read from commit `50f2b476b`. Explicit native definition
policies model the same ten decisions in the baseline, while current policies
execute authored source. The absent-hook cohort executes common fallback.
The selected bodies are unchanged apart from test symbol renaming and removing
internal linkage so the grouped fixture can call each continuation directly.

The cohort covers 224 healthy comparisons: the original 160 catch comparisons,
32 forward/back/up/down throw scheduler comparisons and 32 heavy-pickup/damage
selector comparisons. Declared and absent policies, Bool results, animation-end
results and held-item classification are covered. Sixteen contract records
plus two invalid-result compiler cases, 74 retirement/fault cases and nine
throw mappings run through the actual preparation/runtime. The fixture reports
9,187 checks. CaptureWait's `other.exists` runs
through the real scoped Object payload import. Source faults are also checked
inside four actual outer kernels, preserving completed writes while preventing
later cached native continuation.

Motion entry is a recording leaf with controlled native callback delivery.
Participant retirement, relation loss and owned metadata changes happen at that
callback boundary; actual authored VM division faults also invalidate the
continuation. The throw mapping regression checks that the authored branch
keeps ownership of its `else switch`: donor animation-family selection must not
run after a selected authored mapping, including an out-of-range result.

The heavy damage case mechanically copies the exact dispatch branch from
`ftCo_8008EC90`, with explicit enclosing locals and a continuation marker. It
does not extract or substitute the surrounding full damage/reaction engine.
Capture guards are extracted verbatim from their production bodies. Native
definition callbacks provide equivalent policy decisions in the pinned oracle;
this checks shared scheduler order, not a complete Donkey Kong/Bowser move.

Native presentation, collision, capture geometry and stock item helpers are
controlled recording or aborting leaves. This console proof does not claim
full motion-engine, article construction, DAT loading or tether gameplay
acceptance. No game, window, audio or shared build is launched. Outputs require
a fresh directory on A: and pin the compiler, fixture, production inputs and
headers, rejecting drift before writing a passing receipt.
