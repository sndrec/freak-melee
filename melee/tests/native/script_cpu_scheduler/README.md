# Connected CPU scheduler fixture

This bounded fixture executes actual compiled FMS through the Fighter actor/VM
at native CPU call sites. It extracts complete spacing, grab/attack predicates,
stick outputs, recovery-default and aggregate tick bodies. Large mode/output
policy bodies retain their exact source dispatch prefix; their common native
continuation is an explicit controlled boundary. This is not a complete AI scene.

The native lifetime header validates physical pool/scene/native generation,
userdata/class/kind/data and source program/storage/logical status. Stock and
source defaults, Bool consumption, staged stick outputs and nested caller
retirement/fault/reuse are checked. Geometry, RNG input, stock policy metadata
and unrelated native controls are controlled; no donor source callback is used.

The companion `script_cpu_hook_abi` fixture independently covers all 27 CPU
event argument/result contracts. This fixture concentrates on native ordering,
shared defaults and the CPU caller continuation fences.

All subprocesses are hidden and outputs must go to a fresh A: directory. No game,
global build, user project or commit is performed.

Nine CPU hook paths execute native dispatch into actual FMS. Common spacing,
grab/attack classification and atomic stick results are complete body samples;
initializer/recovery use exact final dispatch/default segments, and mode/output
use their exact native prefixes with controlled shared tails. The aggregate
native tick body checks logical failure before output/counter continuation.
Physical retirement, same-address pool reuse, userdata/native-generation changes
and actual VM write failure with a still-live GObj are covered.

The common CPU file remains 9,237 total lines, below the hard 10,000 limit but
still oversized. A coherent future split is initialization/history/spacing plus
output/mode scheduler kernels with their genuine private helpers, moving bodies
and adjusting direct prototypes/calls. This fixture does not introduce forwarding
wrappers or attempt that static-data refactor during hook acceptance.

Whole native-unit warning exclusions are recorded and compared to unchanged
HEAD body messages under the same headers; a newly excluded diagnostic fails
the runner. No baseline gameplay cleanup is folded into this change.
