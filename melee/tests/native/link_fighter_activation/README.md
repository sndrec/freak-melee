## Common smash binding and boundaries

The initial51 gate exposed five out-of-range common motion declarations58..62:
the real copied extended table begins341. The activation candidate removes those
five declarations and uses `on forward_smash_start` to bind the same accepted
`SwordCombo_Interrupt` helper. Its authored decisions are unchanged.

Production `ftCo_AttackS4.c:decideFighter` chooses facing and delegates to
`doEnter`, which selects the angle variant, changes motion and advances animation,
then invokes the owned start event to bind the interrupt. This gate directly
invokes that generated event after selecting each58..62 motion in the fixture;
it proves the motion is preserved and the installed pointer belongs to the DLL.
It does **not** execute the complete angle/motion/animation entry or prove its
continuation lifetime. Root covers those shared production boundaries separately.
The historical first51 rejection is retained at
`.local/link-fighter-activation51-first/link_ownership.log`.

`caller_closure.md` records actual common callers and remaining scope. The audit
hashes explicit shared entry sources, named-kind sites and callback/census input,
checks CPU/effect policy and rejects private Link union/handler names in generated
C. No additional policy API is required by this composition. Bow fighter phase
and non-unit Boomerang flight replay, all costumes, hidden/muted drawn runtime,
CPU, actual results, rollback/network and renderer acceptance remain separate
gates. These independent candidates remain unregistered; no default promotion is
