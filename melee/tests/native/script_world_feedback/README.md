# Connected source world feedback fixture

Actual source compiler/catalog/VM, Fighter and Item actors/storage, GObj pool,
allocation/free and proc registration execute. Native Camera_RequestQuake,
grLib quake allocation/callbacks, Item rumble, ftLib eligibility helper,
Player_8003544C and lb_80014574 retain mechanically extracted native statements.

Controlled immutable quake model/animation descriptors and HSD model/animation
leaves replace rendering. Loaded rumble pattern data and Player slots are
controlled inputs; only the final hardware queue leaf is captured. No guessed
successful quake/rumble runtime substitutes for the real native paths.

Mutation cases explicitly observe completed quake work or the hardware leaf.
These observations test source/owner/retained-loop guards; they do not claim
native feedback invokes authored script callbacks. Source publication metadata
is controlled, not actual DAT/runtime package loading. No game or audio hardware
is started, and unrelated native bindings explicitly reject.

```powershell
python tests/native/script_world_feedback/run.py --compiler A:/FreakMelee-test-archives/baseline72/compiler/clang.exe --output A:/FreakMelee-test-archives/script-world-feedback-review01
```

Use a fresh A: directory. Every subprocess uses CREATE_NO_WINDOW.

The bounded matrix covers all four quake kinds, all-empty and partially filled
request rows, loop reuse and proc behavior, actual scheduler retirement of
finished nonloop quakes, no-model timer bookkeeping, and raw -0/NaN/Inf position
bits. It compares 32 native feedback cases and executes Fighter/Item feedback
through real VM storage. Rumble cases include duration0/-2 and signed-width
casts, loaded-count/controller/player validation, and native ineligible/no-owner/
non-Fighter no-ops. Source and foreign-owner retirement, pool reuse, data/kind/
class mutation and retained-loop retirement/class changes preserve failed outputs.

The Fighter `controller.rumble(pattern, duration)` matrix compares 480 requests
against the mechanically extracted, unchanged `ftCommon_8007EBAC` function,
covering player/partner eligibility, controller preferences, all loaded patterns
and native duration conventions. A real Fighter helper runs the interpreted
call. Malformed inputs and unsupported contexts reject before the hardware leaf;
seven post-request source/program/schema retirements retain failed outputs.
Hardware is controlled and silent; no game launch or physical rumble occurs.

Captured-item integration compares the actual shared attach/release helper
against the original Yoshi and copied-Kirby routines: four raw attachment bones,
stock/source-owned Items and both destroy-type options (32 comparisons). Native graph attachment,
position transforms, statistics and teardown leaves are controlled and traced.
Actual Fighter/Item actor lifetimes, programs, storage and physical pools remain
connected. Retirement of either actor or the published program stops attach;
release unlinks the old target before destruction, preserving a callback's new
target. This is helper/ownership evidence, not actual JObj constraint geometry
or full capture gameplay. The separate Item scheduler fixture executes actual
captured state selection, inert ticks, actor-state snapshots and destruction.

The same cohort links the production capture binding implementation and runs
prepared Fighter helpers using `capture.has_item`, `attach_item` and
`release_item` against both stock and owned Items. A controlled property router
delegates the capture observation to the actual backend. Missing-target release
is a no-op; malformed argument/type/range, wrong source contexts and retired
relations reject without changing failed outputs. Victim-capture operation
leaves are explicitly unavailable here and covered by their own fixture.
