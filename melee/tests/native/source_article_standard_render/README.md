# Owned Article standard drawing

`render standard` is an explicit Article drawing policy. An omitted policy selects the same standard renderer for an ordinary source Article. Workshop Items retain their existing recipe renderer, which draws a prepared PNG or falls through to that Item's owned Article mesh when art-free. No source constructor reads the physical ItemKind render callback table.

The unchanged native order is GObj creation -> GX link 6/priority 0 registration -> userdata and source actor attachment -> owned Article joint load (or real particle anchor) -> indexed bones/material class/scale/physics/dynamics -> scheduler processes -> spawn initialization -> interpreted Spawned -> guarded native tail. The source program is selected before creation; its identity is checked again after attachment and before model construction. Failure frees the candidate. No draw executes synchronously merely because GX registration occurred.

The standard callback is the existing `it_8026EECC`: primary owned HSD graph, native visibility/camera/outline gates and collision visualization. Neither a Definition nor a generated callback determines source drawing. `model_root`, `model_animation`, and live secondary model slots remain unsupported; accepting standard primary rendering does not imply complete Link/YoungLink or Chain activation.

`native_item_model_admission.c` contains the moved substantive topology proof formerly private to the DATA importer. It simulates native HSD load/postorder ID insertion/instance resolution and the constructor's actual child/next/parent traversal. Indexed graphs must fit the real 100-slot DynamicBoneTable. The nonzero descriptor field enables the table and is not inferred to equal the populated count. Missing mesh permits the native one-joint anchor; unused NULL bone slots keep their existing command semantics. Unknown custom load classes and recursive/unresolved instance topology reject. Both DATA admission and source entity/blueprint preparation call this proof directly, including source indexed models with no DATA. No new dynamics policy was inferred.

## Separate bounded proofs

`run.py --compiler <LLVM directory> --output <fresh A: directory>` compiles actual source Item metadata/preparation, Item actor/execution/VM, GObj ownership and mechanically extracted constructor/source-selection/standard-draw bodies. It installs a deliberately incompatible physical-kind renderer, verifies source registration precedes model load, executes the compiled Spawned body, exercises visibility, rejects invalid drawing/replaced program before model load, and verifies removal during Spawned leaves no live candidate. HSD load/display and physical Item allocation are controlled; physics, rendering platform and unrelated native leaves remain controlled or explicitly unavailable. Program publication lookup is controlled. This does not prove a GPU frame or a complete native scene.

`import_run.py --compiler <clang.exe> --link <owned Link draft> --young-link <owned YoungLink draft> --output <fresh A: directory>` reads copied facts and all three owned DATs without modifying them. Actual imports feed actual source metadata/compiler/ItemPrograms preparation and actual HSD JObj graph construction. Explicit/omitted standard policies agree; custom/duplicate/extra rendering tokens and secondary model metadata reject without replacing an accepted output. Controlled no-DATA graph cases additionally verify 101-node rejection, 100-node admission and the particle anchor. The real Arrow models produce six native primary joints and two model draw roots across both drafts. Constructor/GPU execution is a separate proof above.

The existing `script_item_command_import_validation` runner retains native-topology comparisons and the full retail import corpus after the helper split: 47 cases, 185 Articles, 281 scripts, 25 instance descriptors, all stock fighter archives and 29 stages. Its current admission calls are direct; no old forwarding helper remains.
