# Alternate and companion source family publication

The fixture opens a real ISO and imports its actual common Fighter graph. Its
private alternate draft receives separate `form_activated` hooks before canonical
packet construction. A required companion draft contains the unchanged current
full Popo/Nana sources and independent copied member assets and CPU profiles.
The runner checks both full source files byte-for-byte against the canonical
examples before launching. It writes only new private cache outputs.

Packet construction/cache reading, DAT and resource import, source compilation,
program/table publication, Player registration, leases and retirement all execute
production code. There is no mocked importer, source-package owner or binder.

The grouped cases cover:

- Existing alternate preparation, both required activation hooks, secondary
  compilation failure preserving earlier staged input, kind conflicts, leases,
  retained Windows page-history barriers, clear/restage/direct load and kind
  overflow rejection.
- Companion staging/publication with missing alternate activation hooks. Each
  member still prepares through its own Single source owner; simultaneous mode
  belongs to the enclosing immutable family metadata.
- Unchanged full Popo/Nana source bytes, independent imported Fighter and motion
  data, compiler arenas/banks and actual published program copies. Published CPU
  rows and distance thresholds compare with separately parsed profiles from each
  draft; the test does not assume those profile bytes differ.
- Companion primary/secondary kind mapping with neither `AlternatePair` nor the
  Player alternate-form flag; no actors are created. A companion and an alternate
  family also publish together with distinct character/kind ranges.
- Failed secondary source/CPU preparation preserving staged full companion input,
  whole-family lease/history retirement barriers, complete program/table/mapping
  retirement, and direct companion loading at another valid range.


Use a fresh A: output directory. The companion portrait defaults to `--portrait`
when omitted. The executable receives ISO, alternate draft, alternate portrait,
cache output, companion draft and companion portrait in that order. Its result
JSON includes `full_companion_id`, identifying the generated full companion
packet in the private cache. The runner hashes fixture/production headers,
relevant source, executable and private input bytes and rejects drift. Console
processes use `CREATE_NO_WINDOW`.

This proves package preparation, registration and retirement. It does not prove
companion actor construction, authored Load/CPU startup, eight-actor scheduling,
whole-character gameplay, rendering or transform callbacks. The one-byte retained
page-history probe checks retirement admission, rather than aggregate snapshot
correctness or performance. The earlier 69-check alternate-only receipt remains
historical at
`A:/FreakMelee-test-archives/source-family-runtime-root/receipt.json`.
